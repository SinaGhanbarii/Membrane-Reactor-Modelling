Reactor Model Code Map

Membrane and fuel cell integration · stage 1 model · 16 Nov 2026

How the reactor model is built

A 1D MATLAB model of a Pd-membrane water-gas shift reactor. Every number comes from one parameter register, every physical closure is its own function, one function solves a case, and the studies and figures are built on that. A separate Python model checks the numbers.

Architecture

Five layers, each using only the layers above it

Reading rule: the reactor model never contains a number. It asks the register, through p, so a value changes in one place only.

One run

What happens when run_case is called

  1. Case. make_case takes the register defaults (feed, 400 °C, 4.5 bar, bed geometry, membrane) and replaces any field named in ov. A wrong field name or a bad option stops here with an error.
  2. Solve. Without a sweep gas, or with co-current flow, integrate_bed runs once with an empty permeate stream. For counter-current with a sweep, fzero repeats that integration until the permeate H₂ flow is zero at the far end.
  3. Right-hand side. At every position reactor_rhs evaluates the rate (rate_wgs), the H₂ flux (membrane_flux) and the energy balance, and returns the derivative of species flows, permeate flow, temperature and pressure.
  4. Diagnostics. run_case replays the solution through the same right-hand side to get β, the pinch ratio and the flux at each position, then labels each position with a regime (regime_labels).
  5. Summary. CO conversion, H₂ recovery, atom balance (C, H, O, N) and the share of the bed in each regime. Flags such as EXTRAPOLATED are attached.
  6. Studies. A study file loops over cases, calls run_case for each, and writes one table to results/. Figures read those tables.

The reactor numbers are also reproduced by scripts/ref_reactor.py, an independent Python implementation that reads the same register. Agreement shows the MATLAB code solves the stated equations correctly. It does not show the equations describe the rig.

Extending it

Where a change goes

A new rate law

Add its constants to the register, then a branch in rate_wgs. The reactor code does not change.

A new membrane

Add its permeance parameters to the register and make membrane_flux accept the new name. Select it with struct('membrane', 'M1')-style overrides.

Test-rig data

Enter measured values in the register as reported entries with their source, rerun the studies, and compare outlet conversion and recovery.

Concentration polarisation (H3)

Left out of the 1D model by decision and to be studied in the 2D CFD (OpenFOAM) model. Thin-membrane results from the 1D model are labelled flux-favourable.

Status. This is an unvalidated model. The M7 flux is extrapolated from 1.2–1.6 bar to 4–5 bar, the rate-law unit bases are inferred, and wall heat transfer, bed voidage and effective diffusivity are assumed. Results are model predictions until they are compared with test-rig data.
